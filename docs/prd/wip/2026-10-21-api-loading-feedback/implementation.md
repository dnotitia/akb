## 범위와 남은 검증

- 일반 알림함의 필터 전환 시 기존 행 유지(A16의 선택적 제안)는 적용하지 않았다. 기존 초기/오류/재조회 처리를 유지한다.
- VoiceOver/NVDA 실제 낭독은 수행하지 않았다. DOM 상태, busy 종료, 키보드/기존 접근성 회귀 테스트를 확인한다.
- PDF에서 사용자가 Reload preview를 선택하면 새 URL을 로드하므로 브라우저 내장 뷰어 위치가 초기화될 수 있다. 일반 링크 갱신은 뷰어를 유지한다.
- 운영 API·실제 사용자 데이터로 검증하거나 배포하지 않았다. 브라우저 테스트는 모든 API를 합성 응답으로 격리한다.

## 후속 개선: 문서 진입 로딩 깜빡임

- 최초 문서/본문 스켈레톤은 200ms 뒤에 표시한다. 그 전에는 외곽 레이아웃만 유지하고 빠른 응답은 로딩 표시 없이 바로 본문으로 전환한다. 최소 대기 시간을 강제하지 않는다.
- 페이지 내부 DocumentView는 부모가 방금 조회한 공유 캐시를 사용하며 마운트 직후 중복 재조회를 하지 않는다. 독립 DocumentView의 조회와 명시적 갱신은 유지한다.
- 빠른 완료, 느린 응답, 로딩 중 해제에 대한 단위 테스트와 실제 브라우저에서 문서 API 1회 호출/추가 로딩 없음 검증을 추가했다.
- 로컬 Docker 프런트엔드에 반영했다. 백엔드·워커·DB·MinIO 컨테이너는 변경하지 않았다.
- 검증: 전체 단위 테스트 2,242개, 브라우저 7개 통과. 타입·린트·디자인 검사 및 Docker 빌드 통과.
